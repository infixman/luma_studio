# 前後台改版

course-commerce 之外的一條線：前台和後台「看起來如何、用起來如何」。
分開記，因為它跟課程商務的階段編號沒有關係，而且它的每一步都先出 mock 再動程式碼。

參考來源有三個，各自負責一件事：

- **Orbea 的自行車配置器** —— 產品佔滿畫面、整頁只有一支主色、選項攤平不用下拉。質感。
- **Chat Image** —— header 是浮動膠囊、標籤小聲控制項大聲、選項列帶一行灰字說明、
  代價印在按鈕上。元件的長相。
- **PressPlay Academy 的課程銷售頁** —— 吸附的章節導覽、吸附的購買卡、
  長區塊截斷加「顯示全部」。長頁面怎麼不迷路的骨架。

第三個的**皮**刻意不拿：倒數計時、募資進度條、劃線原價是銷售策略，跟前兩個的克制
不能並存。要不要走那條路是店主的決定，不是設計的決定。

## 第一步：header 變成膠囊

`.site-header` 從一條貫穿到底、底下一條 1px 線的橫條，變成一顆四邊留白、
大圓角、淡陰影的膠囊。

### 這一步能成立，是因為前台的底色本來就不是白的

`storefront/styles/surface.css` 的 `--surface` 是 `#f3ede4`。膠囊要浮起來，
底下就得有東西可以浮 —— 白底上的膠囊只會讀成一個外框，不會讀成一個物件。
所以這一步沒有動頁面底色，比原本估的小。

### 店主的設定全部保留，被拿掉的是幾何

header 的底色、高度、文字色、是否吸附、logo 大小、CTA 都是後台可設定的。
一開始我以為膠囊等於要取消其中幾個，結果不用：**顏色改成畫在膠囊上、高度改成
膠囊的高度**，每個設定都還是原本的意思。真正消失的是「它是一條橫貫的帶子」，
而那從來就不在選項裡。

`bg-transparent` 因此有了一個說得通的意思：沒有底色就沒有膠囊，只剩選單浮在
後面的東西上。`bg-image` 則是把照片跟它的暗色遮罩一起內縮成膠囊的形狀 ——
遮罩不是可選的，它是任何一張照片上傳後選單還讀得到的原因。

### 自訂顏色差點被塗到膠囊外面

固定的那幾個色票是 class，落在樣式表說的地方。**自訂顏色是 inline style，
落在它被寫上去的那個元素** —— 而那個元素在今天以前是會上色的東西，今天以後
是那條透明的外框。沒發現的話，結果是一條橫貫整頁的色帶配一顆白膠囊。

寫了測試釘住「顏色落在 `.header-inner`，而 `.site-header` 上什麼都沒有」。
第二個斷言是必要的：把顏色同時塞給兩者是一個很順手的錯誤修法。

### 捲動狀態只在吸附時才存在

膠囊捲過去之後會縮矮、縮窄、加深陰影。這件事只在 `headerSticky` 時做，
理由有兩個：沒吸附的 header 會跟著頁面捲走，螢幕上沒有東西可以縮；
而後台的外觀預覽用的是同一個元件，它裝在一個面板裡，window 的捲動跟它無關。

用門檻（`scrollY > 8`）而不是捲動位置本身 —— 膠囊只有兩個狀態，更細的東西
只會變成抖動的來源。

### 驗證

七個測試，四個新的全部做過 mutation 驗證：拿掉 class、拿掉 sticky 判斷、
把狀態焊死成 true、把顏色同時塗兩邊，各自讓對應的測試變紅。

CSS 那一半單元測試蓋不到，所以是在跑起來的 dev server 上讀真實的 computed style：
底色 `#f3ede4`、圓角 999px、`colour-forest` 落在膠囊上是 `#2f5d4a`、
捲動後 76px→60px 且 76rem→66rem、`bg-transparent` 時膠囊連陰影一起消失。

（本來想直接開瀏覽器看，但 dev server 的 5173 被另一個專案佔著，換到 5183
會被 API 的 CORS 擋掉整頁資料 —— vite.config.ts 的 `strictPort: true` 加寫死的
埠號讓這件事沒有便宜的繞法。）

## 第二步：課程頁只講一次自己的名字

側欄亮著「課程」、標題列寫著「課程」、然後卡片標題再寫一次「所有課程」，
底下包著的是一張只有一列的表。第三個標題沒有帶來任何資訊，拿掉。

`Panel` 本來就允許不給 title —— 不需要新的元件，只是沒人用過那條路。

### 新增課程從常駐面板變成標題列的按鈕

那張表單一年用不到幾次，卻永遠佔著頁面下半部，而且它擋在清單後面：
要看課程得先跳過它，要新增課程得先捲過清單。移到標題列一顆按鈕加一個對話框，
清單就變成整頁，而那正是這一頁的名字。

### 我差點自己發明兩個 class

第一版寫了 `ui-stacked-form` 和 `ui-form-actions`，測試全綠 —— 因為測試不看 CSS。
兩個都不存在。

`ui-modal-footer` 早就在 ui.css 裡，註解還寫著「取消在左、確認在右，
這個後台每個對話框都這個順序」。而堆疊的欄位根本不需要 class，
`.ui-field` 預設就有下邊距（`.ui-inline-form` 反而要把它歸零）。

送出鈕因此在 form 外面，用 `form="new-course"` 指回去 —— 這招 `CourseEditPage`
的儲存鈕已經用過了。**兩次都是同一個教訓：先去看有什麼，再決定要不要寫新的。**

### 那段規則搬進對話框

「課程只負責教什麼，售價與方案在商品那邊設定」原本是清單上方的一段話，
每次進來都被讀一次，讀的人早就知道了。它是關於「正在做的東西」的規則，
所以搬到唯一有人在做的那一刻 —— 建立課程的表單旁邊。

三個新測試全部做過 mutation 驗證：對話框預設打開、規則搬回清單上方、
標題列不給按鈕，各自讓對應的測試變紅。

## 第三步：後台的灰不再帶黃

`tokens.css` 的中性色原本是照著店面暖過的：頁面 `#faf7f3`、表頭 `#f4f0ea`、
邊線 `#e7e0d7`。白卡片放上去顯得髒，而每一條線裡的黃讓表格看起來像放在太陽下
曬過的文件。

**店面和工具不必是同一組顏色。** 前台是品牌，後台是拿來經營品牌的工具，
而後台這一輪的參考本來就是中性灰白的。暖色留在 `--storefront-page`，
那是給區塊預覽用的，它本來就該長得像店而不是像工具。

「主色就是墨黑，彩色只留給 danger/warning/success/info」這個決定沒有動 ——
被嫌的是灰，不是那個。深色主題也一起中性化，只有 `--primary-text` 的赭紅留著：
那是工作室自己的顏色，而且它是連結色不是灰。

### 圓角從 4px 到 7px

原本的註解寫「4px on everything, the way Strapi does it」。照抄 Strapi 的後果是
在這個尺寸下 4px 看起來像沒設定過。三個名字仍然同一個值，維持原本的慣例。

### `--font-xl` 刪掉了

它只有一個使用者：頂欄標題，2rem。標題不是「特大字」，它是「你在哪裡」，
而導覽列已經把同一個詞highlight 在幾公分外了。改成直接寫 1.05rem，
`--font-xl` 因此沒有人用，留著只會讓下一個人以為有一套用得到的字級。
順手把 `--topbar-height` 從 60px 收到 50px。

## 第四步：後台不再每切一頁就重新載入整個網站

`app.tsx` 直接讀 `location.pathname`，側欄每一個連結都是真的 `<a href>`，
每個跳轉都是 `location.assign`。所以每點一次就是：丟掉正在執行的應用程式、
重新解析、重新啟動，而且因為 `AdminGate` 跟著重新掛載，還要再打一次
`/api/session` 才能畫第一個像素。看起來就是每點一下閃一次只有 logo 的白畫面。

**gate 會擋是對的** —— 沒有辨識出身分之前不該畫出後台的任何東西。
錯的只是對四秒前才辨識過的人再做一次。

### 一個 document 上的監聽器，不是二十個 onClick

連結散在二十幾個元件裡，其中好幾個是由 column 定義生出來的儲存格。
「每個連結都要記得改用 navigate」是一條一定會在下一個新頁面被漏掉的規則。
所以攔在 document 上，既有的 `<a href>` 一個都不用動。

判斷邏輯是單向的：**看不懂的一律讓給瀏覽器**。被讓掉的連結只是比較慢，
被錯誤接手的連結是壞掉。所以中鍵、任何組合鍵、`target`、`download`、
跨 origin、`#` 錨點、已經被 `preventDefault` 的、以及**不在路由表裡的路徑**，
全部放行。最後一條讓 `/auth/logout` 自動留在原本的行為 ——
它必須送到伺服器，而且之後 gate 本來就該重跑。

登出後的 `location.assign('/')` 也刻意留著，理由同上。

### happy-dom 比瀏覽器還兇，害我以為自己寫錯了

「跨 origin 的連結不接手」這條一直紅。原因是 **happy-dom 會在 `dispatchEvent`
當下就真的跟著連結走**，所以等我在事後讀 `location.origin` 時，文件已經移到
`luma-studio.tw` 了 —— 於是「別的 origin」看起來變成「同一個 origin」。
真實瀏覽器是先跑監聽器、才執行預設行為。

修的是測試不是程式：改成在監聽器裡面問，也就是正式環境問它的地方。

這跟之前反覆出現的形狀正好相反 —— 以前是**測試替身比正式環境仁慈**，
這次是替身比正式環境嚴苛，但後果一樣：兩邊各自看起來都對，合起來是錯的。

十五個測試，每一條守則都做過 mutation 驗證（含 `preventDefault` 本身，
以及「導到目前這一頁不要疊 history」）。

## 第五步：畫質選單搬進控制列的齒輪裡

畫質選擇原本是 `LearnPage` 底下另外畫的一排膠囊，浮在播放器外面、跟播放器本身
沒有任何從屬關係——播放器有自己的控制列，控制列外面又長出一排跟它同款式的按鈕，
兩套東西各自看起來都對，合起來卻是同一個播放器有兩層互不知道對方存在的操作介面。
現在跟著 YouTube 的形狀走：控制列右側一顆齒輪，點開是根選單，裡面「播放速度」跟
「畫質」各自一行，各自展開自己的子選單。

### 狀態跟著搬，不是只搬畫面

`renditions`／`level`／播放中的畫質這三個 state 原本養在 `LearnPage`，是因為
選單原本畫在那裡。選單搬進 `LessonPlayer` 之後，這三個 state 也該跟著搬——
`LearnPage` 從頭到尾只是把它們原封不動轉手給畫面用，從沒有自己用過。搬完之後
`LearnPage` 少了一整段：不再需要在切換單元時把畫質重設回自動，因為
`LessonPlayer` 在讀新單元時本來就是全新掛載的（`playbackUrl` 換單元時
一定先變 `null` 再變新值），重設是掛載本身免費附送的，不用再手動做一次。

播放速度也照這個邏輯放：不記憶、預設 1（顯示「正常」而不是數字 1），
選項 0.5／0.75／1／1.25／1.5／2，同一顆掛載保證了「換單元自動回到正常速度」，
不用另外寫一條重設規則。

### 選單本身：根選單／子選單，一個 state 三種形狀

`menu` 這個 state 是 `'closed' | 'root' | 'speed' | 'quality'` 而不是布林——
兩層選單只有一層在同一時間看得到，用一個列舉直接描述「現在畫哪一層」，
比用兩個布林（開／關、根／子）互相打架要直接。點外面關閉用 `pointerdown`
不是 `click`，抄的是後台 `admin/components/ui/Menu.tsx` 既有的作法：
在外面按下的當下就該收起來，不必等放開。

### 只有一個 rendition 不是梯子

沿用原本 `.quality` 就有的規則：畫質那一行只在 `renditions.length > 1`
時出現在根選單裡，播放速度永遠都在——速度是每支影片都有意義的選項，
畫質不是，一支只有一個轉碼結果的影片，選單問「要選哪一個」是問一個
只有一個答案的問題。

## 第六步：音量跟靜音，讀元件而不是記一個數字

播放跟暫停那條規則原封不動搬過來用：按鈕跟滑桿都讀 `<video>` 元件本身的
`volume`／`muted`，不是自己記一份。理由跟播放/暫停一樣——靜音這件事不一定
從這顆按鈕發生（下一步的鍵盤快速鍵 `M`、或者元件掛載時本來就是靜音的），
一個只聽自己按鈕的標籤，遇到別的路徑改了元件，就會說謊。

`volumechange` 事件補進原本那組 `bindings` 陣列裡，跟 `play`／`pause`／
`durationchange` 同一套機制：改元件屬性、觸發事件、螢幕上的東西才跟著動，
不是反過來由畫面去驅動元件。

滑桿本身沿用 `.player-scrub` 的作法：真正的 `<input type="range">`，
外觀交給 CSS 的 `::-webkit-slider-thumb` / `::-moz-range-*`，拖曳、鍵盤、
無障礙的部分讓瀏覽器自己處理。

## 第七步：劇院模式，播放器只講旗標，版面是頁面的事

`LessonPlayer` 自己多一顆按鈕跟一個 `theater` state，不記憶（跟播放速度
同個理由：每次掛載都是新單元，不該幫忙扛著上一支影片的版面選擇）。
但「撐寬播放器、收起右側目錄」這件事本身不歸播放器管——播放器不知道
自己旁邊擺了什麼，收起隔壁的目錄是 `LearnPage` 的版面決定,不是影片的。

所以介面上只加一個 `onTheaterChange?: (active: boolean) => void`：
播放器改變自己的旗標時喊一聲，至於喊了之後版面要怎麼反應，是接聽的人的事。
`LearnPage` 接住之後只做一件事——幫 `.learn-layout` 掛上 `is-theater`，
真正收起 `.learn-outline`、把兩欄併回一欄,全部留給 CSS。

### 意外抓到的一個 bug：測試 fixture 的到期時間寫死在 2023

寫這步的整合測試時,點兩下劇院按鈕的結果一直被靜悄悄吃掉——不是拋錯,
是 `LessonPlayer` 在兩次點擊中間被整個重新掛載,把它自己的 `theater`
state 歸零。追下去發現 `LearnPage.test.tsx` 的 session fixture 把
`expiresAt` 寫死成 `1_700_000_900`(2023 年底),而這台機器現在的實際
時間已經是 2026 年——`renewDelay` 拿真正的 `Date.now()` 算「還剩幾秒」,
算出來已經是負的,夾在 0,於是每次 `open()` 都立刻排一顆幾乎零延遲的
`setTimeout` 再呼叫自己一次。兩個 `await settle()` 中間那二十個 tick,
真實計時器就夠這個迴圈跑上好幾輪,播放器被反覆拆掉重建,兩次點擊之間
的狀態自然保不住。

這條迴圈本來就在,只是原本兩個測試都只在掛載後立刻斷言,從沒有給它
機會發作。修法是把 fixture 的到期時間換成「跑測試那一刻」的一小時後
（`Math.floor(Date.now() / 1000) + 3600`),不再綁死一個會被時間追上的
數字。

## 第八步：鍵盤快速鍵,都是按鈕已經在做的事

空白／K 播放暫停、←→ 快轉倒轉五秒、↑↓ 音量增減、M 靜音、F 全螢幕、
T 劇院——每一條都直接呼叫按鈕自己在用的那個 callback（`toggle`／
`toggleMute`／`toggleFullscreen`／`toggleTheater`),沒有另外寫一份
「M 是什麼意思」。兩份邏輯遲早會分岔,而分岔的那一天不會有測試告訴你。

### 監聽掛在播放器自己身上,不是掛在 `document`

這幾個字母（M、F、K、T）都是頁面在別的地方可能正常用到的鍵。掛在
`.lesson-player` 這個 `tabIndex={0}` 的容器上,只有焦點在播放器裡面時
才會生效,不會從頁面任何角落打字都觸發播放/暫停。

### 進了 `<input>` 就讓開

畫質音量滑桿、進度滑桿本身也吃方向鍵——原生的 range input 收到 ←→
會自己走一步。如果播放器的鍵盤監聽器不分青紅皂白全部接管,使用者在
音量滑桿上按 ← 想把音量調低一格,同一個按鍵会被播放器自己的處理器
再解讀成「倒轉五秒」,兩件事同時發生。處理器一開頭就檢查
`event.target.tagName === 'INPUT'`,是就整個放行,原生行為留給瀏覽器自己接。

### 快轉倒轉不越界

`seekBy` 夾在 `[0, duration]` 之間——`duration` 還沒讀到（`NaN`）時上界
當作沒有,只夾下界,避免影片還沒量到長度就被鎖在 0 秒動彈不得。

## 第九步：控制列閒置自動隱藏

播著播著,滑鼠不動、手指不碰,控制列自己淡出,讓畫面底下不再有一條
擋著構圖的橫條——跟 YouTube 一樣的行為,但只在三個條件同時成立時才
生效：正在播放、設定選單沒開著、而且真的有一段時間沒人碰它。
`idle` 這個 state 只描述「現在該不該淡出」,`wake()` 這個函式描述
「什麼時候該把倒數重新開始算」——滑鼠移動、觸控、任何鍵盤按鍵,
都呼叫同一個 `wake()`,不是各自維護一份「什麼算是活動」的定義。

### 暫停跟選單開著,是不淡出的例外,不是淡出的延後

`wake()` 的判斷式是「有在播放 `&&` 選單關著才排定隱藏」——不是「暫停時
延後隱藏」。差別在於：暫停或選單開著的當下,`idle` 立刻變回 `false`,
不用等已經排定的 timer 跑完。一支暫停的影片是使用者很可能正要動手做
什麼的影片,選單也沒有下面那條看不見的控制列可以依附。

### 淡出用透明度,不用收起版面

`.player-bar` 隱藏時只是 `opacity: 0` 加 `pointer-events: none`,版面
高度不變。播放器自己的背景跟控制列的背景都接近純黑,所以淡出之後
底下不會露出一塊「控制列消失後留下的縫」——兩個黑幾乎分不出界線。
比起把控制列整個收起來（`display: none` 或 `height: 0`),這樣不會在
淡出、淡入的那一刻讓畫面高度跳動。

### 這一步踩到的坑：fake timers 在這裡讀不出 preact 的排程

一開始想用 `vi.useFakeTimers()` 加 `vi.advanceTimersByTimeAsync()`
來跳過三秒等待,寫完發現不管怎麼 flush,`playing` state 改變之後
UI 從來沒有反映出來——不是隱藏邏輯錯,是 preact 在 happy-dom 底下
用 `requestAnimationFrame` 排程重繪跟 effect,而 vitest 的假時鐘
推進在這個環境沒有把它一起推進。換成真的 `setTimeout` 硬等
`IDLE_HIDE_MS + 200ms`,問題就消失——測試因此變慢了幾十秒,
但測的是真正的排程,不是另外發明一套「所謂的之後」。
