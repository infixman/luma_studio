# 後台改造 — 一套設計 token、一個外框、一組元件

2026-07-28

## 起因

後台是一頁一頁長出來的：九個 CSS 檔各自寫死顏色，控制項用的是瀏覽器原生的
`<select>`、`<input type="checkbox">`，刪除確認用的是 `confirm()`——那東西的長相由作業系統決定，
設計上完全碰不到。結果就是每一頁都「差不多」，但沒有兩頁真的一樣。

現況盤點：11 頁、11 個元件、約 5000 行 TSX 與 2300 行 CSS，其中 73 個 `<input>`、
13 個 checkbox、6 個 `<select>`、17 次 `confirm()`。

## 決定

### 1. 顏色不再寫死，且深淺兩用

所有顏色收進 `admin/styles/tokens.css`，以語意命名（`--surface`、`--raised`、`--text`、
`--muted`、`--border`、`--primary`…），不是以色名。深色與淺色各一組值，同一組名字。

主題來源有兩個，順序是：使用者選過的優先，沒選過就跟系統走。

```
:root                        → 淺色（預設值）
@media (prefers-color-scheme: dark) :root:not([data-theme]) → 深色
:root[data-theme="dark"]     → 深色（使用者選的，蓋過系統）
:root[data-theme="light"]    → 淺色（使用者選的，蓋過系統）
```

`:not([data-theme])` 是關鍵：沒有它，系統是深色時使用者就選不回淺色。

主色沿用現有的 teal，不換成 Strapi 的紫。後台的識別已經是這個顏色，換掉是為了像別人而丟掉自己的。

### 2. 外框：圖示軌 + 側欄 + 內容標題列

頂部分頁列換成三段式：

- **圖示軌**（56px）：分區圖示，滑過出現名稱。分區是「內容 / 商店 / 設定」這種層級，不是九個並列的分頁。
- **側欄**（240px）：目前分區底下的頁面清單，含搜尋與數量徽章。
- **內容區**：固定在頂端的標題列，標題在左、主要動作在右。捲動時標題列不動——一頁很長的表單，
  「儲存」不該要捲到底才找得到。

九個並列分頁在數量少的時候可以，現在已經九個了，再加就得換行。分兩層之後每一層都短。

### 3. 元件庫，不是原生控制項

`admin/components/ui/`：Button、IconButton、TextField、TextArea、Select、Checkbox、Radio、
Toggle、Badge、Panel、Table、Modal、Tabs、Tooltip。

`<select>` 改成自訂的 listbox（原生的下拉選單長相由作業系統決定，跟 `confirm()` 同一個問題），
但**鍵盤行為要自己補回來**：上下鍵移動、Enter 選取、Esc 關閉、Home/End、輸入字母跳字。
沒有補回來的自訂下拉是退步，不是進步。

17 次 `confirm()` 換成 `<Modal>`。原生的那個會凍住整個分頁，而且說不出「刪掉的是哪一個」——
只能給一句字串。換掉之後刪除確認才講得出被刪的東西叫什麼。

## 順序

1. token 與主題切換
2. 外框
3. 元件庫
4. 11 頁逐頁搬上元件庫
5. 清掉被吸收的 per-page CSS，兩個主題各驗一次

前三步是地基，可以先驗收；第四步才會動到每一頁的 markup。

## 不做

- 不引入 UI 框架。這個後台只有一個使用者，帶進一整包相依與它的升級責任不划算，
  而需要的元件就上面那十幾個。
- 前台不套用。前台是店面，有自己的暖米色與版面，後台是工具。
