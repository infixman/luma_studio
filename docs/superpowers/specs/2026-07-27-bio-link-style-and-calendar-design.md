# Bio link：外觀自訂與行事曆（2026-07-27）

兩個獨立功能，落在同一個編輯頁與同一張設定表，因此寫在一份文件裡。

## A. 外觀自訂

### 目標與非目標

擁有者不寫 CSS 也不寫 JS。因此**不提供顏色選擇器、不提供自訂 CSS 欄位**。給的是幾組已經配好的主題，加上兩三個具名選項，改完立刻看到結果。

限制選項不是為了少做，是為了保證結果可用：開放調色一定會出現淺灰底配白字這種讀不到的組合，而擁有者沒有工具判斷對比度是否足夠。由系統負責這件事。

### 資料模型

`bio_link_settings` 增加三欄：

| 欄位 | 值 | 預設 |
| --- | --- | --- |
| `theme` | `warm` \| `ink` \| `forest` \| `sand` \| `night` | `warm` |
| `button_shape` | `rounded` \| `pill` \| `square` | `rounded` |
| `font_style` | `sans` \| `serif` \| `rounded` | `sans` |

### 實作方式

每個主題是一組 CSS 自訂屬性（背景、卡片底、文字、次要文字、強調色、邊框）。公開頁在容器上標記 `data-theme`、`data-shape`、`data-font`，樣式表依此切換。

**使用者輸入永遠不會變成 CSS。** 值只在後端驗證過的固定集合內，前端只用它們挑選既有的樣式規則。沒有任何字串被插進 style 屬性或樣式表，因此不需要為此放寬 CSP。

每組主題的文字與背景對比度在設計時就確保達到 WCAG AA（一般文字 4.5:1）。

### 編輯介面

三排選項按鈕，沿用列印規格已經在用的樣式。右側一塊即時預覽，用同一組 CSS 變數畫出縮小版的頁面骨架——頭像圓、名稱、兩顆按鈕、一排 icon。改任一選項立即反映，不需要開新分頁。

## B. 行事曆

### 連接方式

擁有者在 Google 行事曆建立一個**專門放公開課程**的行事曆，複製它的 iCal 網址貼進編輯頁。

選這個而不是 OAuth 挑選器的理由：`calendar.readonly` 是 Google 定義的敏感權限，加上之後，Testing 狀態的 app 所發出的 refresh token 七天後過期，行事曆會每週斷線；送審發布則要提交隱私權政策與用途說明，審核數天到數週。貼網址完全避開這條路，而且兩者的最終能力相同——**都是唯讀**，事件永遠在 Google 行事曆裡編輯。

用專門的行事曆而非個人行事曆，是這個設計的一部分：私人行程留在原本的行事曆，結構上不可能外流。

### 資料模型

`bio_link_settings` 再增加四欄：

| 欄位 | 說明 | 預設 |
| --- | --- | --- |
| `calendar_url` | iCal 網址，空字串表示未設定 | `''` |
| `calendar_title` | 區塊標題 | `近期課程` |
| `calendar_count` | 顯示幾筆 | `5` |
| `calendar_enabled` | 是否顯示區塊 | `0` |

### 網址驗證

只接受 `https`，且主機必須是 `calendar.google.com`。

這不是形式檢查。後端會用這個網址發出請求，若接受任意主機，管理端點就成了一個可以打內部位址的跳板。限制主機把這個能力關掉。

### 取得與快取

以 `cf: { cacheTtl: 900, cacheEverything: true }` 取得，因此連續造訪不會反覆打 Google，擁有者在 Google 改完後十五分鐘內反映。

不另外寫進 D1：這條路徑是公開的，多一個定期寫入就多一份消耗共用寫入額度的途徑。

### ICS 解析範圍

自行解析，只取需要的欄位：`SUMMARY`、`DTSTART`、`DTEND`、`LOCATION`、`UID`。

**重複事件**（`RRULE`）必須支援——週課是這個功能最主要的用途，而 Google 的 ICS 不會把重複事件展開，只給規則。支援範圍：

- `FREQ` 為 `DAILY`、`WEEKLY`、`MONTHLY`
- `INTERVAL`、`COUNT`、`UNTIL`、`BYDAY`
- `EXDATE`（取消的單次）

**不支援**：`BYSETPOS`、`BYMONTHDAY` 等進階規則，以及 `RECURRENCE-ID` 的單次覆寫（改了某一次的時間或標題）。這些在課程排程中少見，遇到時該次事件會以原規則顯示或被略過，不會讓整個區塊失敗。

時區：`DTSTART;TZID=Asia/Taipei` 視為 +08:00，結尾為 `Z` 的視為 UTC，純日期視為全天事件。其他時區以 UTC 處理並在文件中註明。

展開只做到「往後 60 天內、最多 `calendar_count` 筆」，因此規則寫錯也不會產生無限迴圈。

### 公開資料

`/api/bio-link` 的回應增加：

```json
"calendar": {
  "title": "近期課程",
  "events": [
    { "id": "...", "title": "...", "start": "2026-08-03T10:00:00+08:00",
      "end": "...", "allDay": false, "location": "..." }
  ]
}
```

未啟用或未設定時為 `null`。

包含 `DESCRIPTION`（擁有者選擇）。**該欄位會完整出現在公開頁上**，所以編輯頁會在行事曆設定旁註明：說明欄不要寫學員姓名或聯絡方式。

### 顯示

排在連結按鈕之後、頁尾之前。每筆一張卡片：左側日期徽章（月日與星期），右側標題、時間區間、地點。

每筆提供「加入行事曆」：

- **Google 行事曆**：連到 `calendar.google.com/calendar/render?action=TEMPLATE&...`，涵蓋多數使用者
- **`.ics` 下載**：由後端 `GET /api/bio-link/events/{id}.ics` 提供，涵蓋 iPhone 與 Outlook

`.ics` 由後端產生而非瀏覽器端組 Blob，因為 CSP 的 `default-src 'self'` 會擋掉 `blob:`，而放寬 CSP 只為了省一個端點並不划算。

## 錯誤處理

行事曆抓取失敗或解析失敗時，**整個區塊不顯示**，頁面其餘部分照常。行事曆是加分項，不該讓連結頁打不開。

編輯頁則相反：測試網址失敗要明確告訴擁有者哪裡錯了，否則他無從修正。編輯頁提供「測試連線」按鈕，立即回報抓到幾筆事件。

## 驗證方式

- ICS 解析器以實際的 Google 行事曆匯出樣本測試，涵蓋單次事件、全天事件、週重複、帶 `UNTIL` 的重複、帶 `EXDATE` 的重複、跨時區。
- 網址驗證測試涵蓋非 https、非 Google 主機、內部位址。
- 主題值的驗證測試涵蓋未知值。
- 每組主題的對比度以計算驗證，而非目測。
