# 待辦與已知缺口

2026-07-27 整理。每一項寫下「是什麼」「為什麼重要」，以及已經做過的判斷，讓之後接手的人不需要回頭翻對話。

順序是我建議的優先度，不是規定。

## 營運風險

### 1. 排程會在 60 天無 commit 後被停用

GitHub 的規則：repo 連續 60 天沒有活動，所有 `schedule` 觸發的 workflow 自動停用。備份與 canary 都會停，而你可能沒注意到那封通知信。

**建議做法：搬到 Cloudflare Cron Triggers。** Worker 本身可以排程，沒有無活動規則。附帶好處更大——備份改用 D1 與 R2 的 binding，不再需要 API token、wrangler CLI 與 REST API。2026-07-27 那天備份卡了一小時，根源就是 REST API 的 token 權限（先 `10000` 後 `7403`），binding 完全避開這一類問題。

代價：canary 從 Worker 內部執行會失去外部視角。但 Worker 可以 `fetch` 自己的公開網址，請求會真的繞出去經過邊緣再回來，DNS、Custom Domain、WAF、前端 Worker 都仍然被驗到。實際損失小。

搬完後 GitHub Actions 只剩部署，而部署本來就在 commit 時才跑。

### 2. 失敗只寄 email

ibon 壞掉的緊急程度是「客人現在站在超商裡」，而 email 可能幾小時後才看到。

Discord 或 Telegram webhook 約十分鐘可完成，Worker 直接 `fetch` 出去即可。LINE Notify 已停止服務，走 Messaging API 設定成本高很多。

### 3. R2 的圖檔沒有備份

D1 每天備份，但客人的作品圖只有一份。R2 沒有內建的版本或快照。

可行做法：排程把 R2 物件複製到另一個 bucket，或定期下載。要先想清楚保留多久——圖檔比資料庫大得多。

### 4. 分散式來源的資源耗盡仍無解

單一 IP 的洪水有 WAF 規則和 Worker 內的限制器擋著。分散來源需要付費方案的 Managed Challenge。目前接受這個風險。

## 品質與正確性

### 5. 公開頁從未做過無障礙檢查

取件頁是客人在超商用手機開的。對比度、觸控目標大小、鍵盤操作、螢幕閱讀器標籤都沒驗過。

### 6. 還原腳本沒有對真實備份檔跑過

`scripts/restore-d1.py` 用合成資料驗證過，包含單引號、雙引號、NULL 與中文，產生的 SQL 也實際灌進 SQLite 驗過。但沒有拿 R2 上的真實備份跑過一次。備份最糟的失敗模式就是「以為有、要用時才發現沒有」。

### 7. 速率限制綁定在正式環境沒驗證過

`[[ratelimits]]` 的行為無法在本機測試。程式碼寫成失敗即放行，所以最壞情況是「限制沒生效」而不是「網站掛掉」，但目前沒有證據顯示它真的在限流。部署後可以連打 `/auth/login` 十幾次確認會不會拿到 429。

## 設計與功能

### 8. 分享卡片的標語超出中央安全區

標語寬約 770px，但不同 app 與情境會用不同比例**置中裁切**同一張圖。方形裁切只保留中央約 630px，標語兩端會被切掉。縮小字級或拆成兩行即可。

### 9. 分享卡片可以改用實際照片

現在是 logo 文字標。學員作品照或教室照在動態牆上更容易讓人停下來。做法：照片打底 + 半透明暗層 + logo 與標語壓在上面。

### 10. bio link 頁的 QR code

印在名片、課堂講義或展場上。

### 11. 主題與配色自訂

原本規劃的 P3。背景色、按鈕樣式與圓角、字體、文字色。

### 12. 連結排程上下架

原本規劃的 P5。限時活動的連結到期自動隱藏。

### 13. 每個連結的縮圖

Linktree 有。連結多的時候辨識度差很多。

### 14. 統計匯出 CSV

### 15. 商城的 SEO，以及拿掉整站的 `noindex`

`frontend/index.html` 有 `<meta name="robots" content="noindex, nofollow">`。那是 ibon 列印工具時期的設定——當時整個站就是給特定客人用的。商城要被找到就得拿掉它。

**刻意還沒做。** 網址結構正在變：頁面系統、選單與自訂頁還會新增和改動路由。現在被收錄，之後改網址就要處理 301 與排名重置；現在沒被收錄，改動是零成本的。而且資料庫裡還沒有商品，收錄一間空店只會讓爬蟲抓到空殼，真的上貨後還得等重抓。

拿掉那一行只是開始。真正要做的是：

- 每頁的 `<title>` 與 `meta description`
- 商品的 JSON-LD（Product / Offer），讓價格與庫存出現在搜尋結果
- `sitemap.xml`
- canonical——分類頁的 `/shop/c/a,b` 與 `/shop/c/b,a` 是同一批商品的兩個網址
- 各頁的 OG 分享卡片

**不需要改成 SSR。** [frontend/worker/storefront.ts](../frontend/worker/storefront.ts) 已經在為名片頁做這件事：偵測到爬蟲時，先打 API 取內容再把標籤注入 `<head>`，一般瀏覽器不必等那次往返。商品頁與分類頁用同一套擴充即可。「SPA 沒辦法做 SEO」的直覺在這個架構下不成立，值得寫下來，免得有人為此提議重寫。

`noindex` 要保留在後台（`admin.html`）與 `/checkout`、`/orders` 這類頁面上。

時機：自訂頁那幾塊做完、有真實商品、準備開賣前，一次做完。
